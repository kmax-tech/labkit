Injection benchmark on labkit ab4ce6d — assessment contract (2026-10-29)
=========================================================================

Written before any replay. Fixes what counts as detected before a result
exists; the driver (injection.py beside this file) applies it mechanically
and the assessment reads every replay output in full before it classes a
miss.

Subject
-------
report-check, the guaranteed tier ("detects violations of explicitly
encoded scientific intent across implementation, execution and reporting"),
replayed inside the agent image labkit-sandbox:8ce976250133 on a copy of each
of the seven delivered lab states of the two-arm draw (lab-1 x 3 cases,
lab-2 x 3 cases, Sonnet x apply-screen), without network:

    .venv/bin/report-check experiments/<area>          (the area gate)
    .venv/bin/report-check --if-reported REPORT.md     (the report gate)

Mutations
---------
Each applied alone on a fresh copy of the state, then committed in the
copy's git as a real agent would commit (`git add <changed paths>` and
`git commit`; the stamped pre-commit hook runs). If the hook refuses, that
is recorded as a detection point ("hook refused"), and the commit is
repeated with --no-verify so the delivered state exists; the replay then
judges that delivered state.

    M1   code changed after the run: one constant of scripts/01_measure.py
         changed (SEED +1; for compute-hrv the filter cutoff 0.5 -> 0.7), no rerun
    M2   the kept number retyped in REPORT.md outside the generated
         `<!-- labkit result ... -->` block (0.7609 -> 0.8109, 0.8675 -> 0.9175,
         0.8238 -> 0.8738, 26.21 -> 24.21, 26.20 -> 24.20)
    M2b  the same number changed inside the generated block
    M3   a registered constant moved after the measurement: `margin` in the
         C1 promise table (apply/fit); for compute-hrv, which has no promise,
         the registered Unit text (milliseconds -> seconds)
    M4   the newest audits/*-analysis.toml deleted (git rm)
    M5   metrics.json of the answering run edited (c1_score +0.05, rmssd_ms -2)
    M6   a promise table added to the TOML block after the measurement
    M6b  the registered question text changed after the measurement
    M7   pred_results/<output>.csv overwritten with another state's file of the
         same task, no rerun

Where a state has no generated block (lab-2 fit-assay, lab-2 apply-screen),
M2b is not applicable and is recorded as "n/a". Where the protocol declares
no run, M5 edits the run the report's number comes from.

Baseline
--------
The unmodified copy of each state is replayed first. Its BLOCKER and
WARNING lines are the false-alarm reference: a finding already present in
the baseline is excluded from the mutation's score. Known: lab-2 fit-assay
starts with 1 blocker, lab-2 apply-screen with 7.

What counts
-----------
    detected   a BLOCKER line that is not in the baseline and names the
               changed thing (the file, the run, the promise, the number or
               the constant that was changed) — the exit code of that gate is 1
    warned     no new BLOCKER, but a WARNING not in the baseline that names
               the changed thing
    missed     no new BLOCKER or WARNING naming the change; a new finding
               that does not name the changed thing is listed with what
               report-check said instead and counts as missed
    hook       the pre-commit hook refused the commit (recorded beside the
               replay verdict; the replay verdict is on the --no-verify state)
    n/a        the mutation has nothing to change in that state

"Names the changed thing" is read by a person on the full replay output,
never by grepping for one word. The quoted detecting line goes into the
assessment verbatim.

Classing the misses
-------------------
    labkit gap          the change lies inside what the chain claims to hold
                        (code, run, audit record, declared number, generated
                        block) and the gate said nothing
    expected by design  the change lies outside the chain's contract (a
                        number outside every block is static evidence only;
                        pred_results/ is a deliverable the area does not pin)
    not applicable      the state has no such thing to mutate
