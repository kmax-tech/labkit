# Count and judge at `seconds` after the fixes — cold Sonnet agents on 22483de (2026-10-20)

*The same six tasks as the db1695d series
([report](2026-10-20-cold-probes-db1695d.md)), re-run after its tool fixes
and an independent review of them. Main measure: operating friction —
wrong calls, repairs, manual interventions. All six numbers came out bound,
the count right every time. Misuse of labkit fell from 11 calls in the
three count runs to 1, and from 2 to 0 in the three judge runs; the one
left is the hand-written audit decision the fixes only eased. Scores:
`2026-10-20-sonnet-22483de-<probe>.score.json`.*

## Setup

- **Code:** `git archive 22483de5cd54592ac5c2169fd05b3a2f58c275fd`,
  installed non-editable with pytest (the rest of the stamped
  `requirements.txt`), Python 3.12.7. One env per probe, all built before
  the first probe, every `pip freeze` equal. Stamped with
  `usability stage --venv env-<probe>`, tier `seconds`; scaffold sha
  `4fb28702943e` for all six — freshly stamped areas, so the fixed
  templates are in them. No change to the tested state during the series.
- **Agents:** Sonnet subagents of the operator's session, each handed only
  its `<probe>.prompt.md`, one after another. The probe's Claude hooks do
  not fire for a subagent; the git pre-commit hook and `runlog` do.
- **Machine:** `caffeinate -i` held it awake; `pmset` shows no sleep.
- **Measures, fixed before the first probe:** a script lists every shell
  result with `is_error` or a failure mark (Traceback, `Exit code N`,
  `usage:`, `error:`, `no such`, `not TOML`, `refuse`, `BLOCKER`,
  `MISSING`); the operator classifies each as *misuse* (labkit refused or
  crashed because of how it was called), *gate* (a check doing its job on
  the content), *outside* (shell, harness, environment) or *false* (the
  mark inside data or a finding's text). Checked first on db1695d count-3,
  where it lists every known failure. Agents chain commands, so exit codes
  alone find a fraction (one of three known failures there). After
  count-2 one rule was added without changing the count: a failure the
  agent reports that carries no mark (a BSD `sed` error) is noted apart.
- **Comparison:** the db1695d runs classified the same way, after the
  fact; judge-1 there is left out (the laptop slept), judge-2..4 count.
  db1695d had no pytest in its envs, so its area tests did not run.

## Incident: the shared `/tmp`

Probes were isolated by directory and env, not by `/tmp`. db1695d's
agents had left files there; judge-2 named its audit output
`/tmp/j2_audit.out`, as db1695d judge-2 had, and read the old file first.
A foreign run id gave it away and it reran, so its number is its own — but
it saw another probe's output and was not fully cold. Between judge-2 and
judge-3 every probe leftover was moved out of `/tmp` (nothing deleted).
Next series: one `TMPDIR` per probe.
