# Smoke test of 0.108.0 on the three SAB-shaped probes — three cold Haiku runs, every number right and bound, no hook and `next` at odds (2026-11-04)

*The three `usability stage --task` probes (compute-hrv, fit-assay,
apply-screen: a ScienceAgentBench-shaped task each, a known trap, a
hidden evaluation of `pred_results/`), stamped with labkit v0.108.0
(`da46ce1b`), one cold Haiku subagent per probe with only the probe's
prompt (`<dir>.prompt.md`), scored with `usability score --transcript`
on the subagent's transcript. The purpose, before the usage round in
labkit-paper area 19: do agents reach the two states the one-explainer
pilot changed, and does `labkit-next` name the same step the hooks hold
on there? Not a comparison, not a statistic: one run per task.*

## Result

The target "one kept number under 5 min" is missed by all three, as by
every cold run before; the time goes to the audit and review loop (two
to three model calls of about two minutes each) and to adapting the
stamped measurement template (1000 lines for a fit or an apply).

**The two states the pilot changed, as the transcripts show them.**

- *Measured, registered report without its account:* `labkit-next` named
  the progress account with the run id (`--discuss … --into REPORT.md`)
  in compute-hrv and fit-assay; both agents took it, then `next` named
  the analysis audit, then (compute-hrv) the adoption and "nothing holds".
- *A report discussing a run owes its review:* in fit-assay the commit was
  refused once, until the report review named no claim (three draws: the
  agent's own wording contradicted the audit record twice); `next` after
  the handover said "nothing — a new attempt is a new registration", the
  review already done. In compute-hrv the report review found one
  contradiction the agent fixed, the second draw released.
- No case where a hook held on one thing while `next` named another.

**fit-assay's handover is the audit working:** the agent compared four
model settings by cross-validation before registering, wrote
`type = "confirmatory"`, and the analysis audit named the undisclosed
selection as a BLOCKER; the agent handed over rather than decide it as a
limitation, with the number measured and not adopted. The hidden
evaluation passes anyway — the trap is the registration, not the model.

## Instrument findings

- `agent_transcript` refused the subagents' transcripts: Claude Code
  2.1.x writes `api-request-blob` records with a `message` hash and no
  timestamp. Fixed the same day (`9540523c`): only `user` and `assistant`
  records are read, every other type is bookkeeping.
- `usability log TAG TEXT -- CMD` hides CMD from the trace's "labkit
  commands" count (it reads the first word, `usability`); the counts
  above are from the command texts, not that line.
- Two agents called a `usability edit` that does not exist (the log
  contract names tags, not subcommands); one agent's `protocol-fill` call
  with several fields was refused whole because one field was already
  filled, and the rest were written on a second call.
- Placeholder fields of the Context section (Problem, Prior threads,
  Yield per stage) surfaced only at the audit, not before the run.
