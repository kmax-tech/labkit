## Open points for labkit

1. The not-reported marker in backticks (``Run `<id>` (not reported: …)``)
   is not recognised: accept Markdown code spans around the id in
   `report_blocks._NOT_REPORTED`, with a twin test; or the refusal names
   the form it did not read (t3).
2. `git commit --no-verify` passes every pre-commit gate: the pre-run hook
   (PreToolUse on Bash) could refuse it, or the stop hook could run
   report-check on a REPORT.md committed with it (t3).
3. The report review's hint was not followed (t18); with the marked run's
   numbers left in the report, the hint alone does not change the report.
   Whether the review should run itself at the commit (one model call) or
   hold is the author's decision; this round is one case for it.
4. Deleting failed audit records (`rm audits/*.toml`, t18): the failed
   record is evidence the stop hook or report-check could miss once gone;
   at least the next audit could name a failed attempt it no longer finds
   (round six had the same on finding records).
5. The two-model claude-cli reply (t18, three times): check against the CLI
   whether a second model in `modelUsage` (opus-4-8 beside opus-5-5) means
   the answer is not the requested model's, or an internal helper call; if
   the latter, the audit failed falsely (round seven's point 3, now with the
   cause named).
6. A rejected decision that is lost after a claim edit (t5, 08-48 #2,
   judge's suspicion): check whether a changed Conclusion drops the review's
   rejection to a "not reviewed" WARNING.
