## Systematic faults of labkit

1. **A registration change names only part of what changed.** apply-screen
   changed `margin`, `null_band` and the three promise sentences in one
   edit after its first measurement. report-check named
   `[A2] null_band 0.1 → 0.15; [C1] margin 0.25 → 0` and its way out
   "restore … ([A2] null_band 0.1 back; [C1] margin 0.25 back)". The agent
   restored exactly those, measured, finalized and audited again, and was
   held again for "a promise's sentence". `promises.snapshot_changes`
   names a sentence change only when nothing else changed
   (`labkit/formats/promises.py:132`): the run record keeps sentences
   only through the block's digest. The delivered state still carries it.
2. **A changed registration shows only at the adoption.** apply-screen
   measured twice and audited once, fit-assay measured twice, under a
   registration changed after the first measurement; `finalize` named no
   registration change after any of these runs and ended at "0 blockers"
   or "all clear", which the agents read as green. The check
   (`report_check.registration_changes`) runs at report-check and
   `protocol-fill --from-run` only, after the audit was paid for.
3. **An audit record deleted before it was staged is lost, and the way
   out offers restores that cannot work.** The pre-commit held fit-assay's
   commit: "in the tree, not in the index … stage it (`git add …`)". The
   agent ran `rm` on the record and committed in the same command; the
   commit passed, since `claude_hooks.undecided_state` reads the journal
   as the index holds it and the journal was never staged. From then on
   `labkit-audit` and the report review refused the area ("restore it
   (`git checkout HEAD -- …` when committed, `git add` when only
   unstaged)" — neither applies to a file never staged), and the only
   way left was the handover. The journal copy in the git directory
   kept the journal line (the agent restored the journal from it), not
   the record. The agent ended with "TASK COMPLETED … Criterion: PASSED"
   while report-check held.
4. **[C1]'s bar rests on one null draw.** The skeleton passes [C1] when
   the registered lane reaches the null lane plus `margin`
   (`measure-estimator-script.py.template:61`); at apply the null lane is
   one permutation of the gold, at fit one refit on permuted labels. Both
   analysis audits flagged it as a BLOCKER: fit-assay's first run passed
   with `c1_score` = `c1_threshold` = 0.7625 (one more null item correct
   flips it); apply-screen's bar was 0.478 (one permutation, chance 0.501) +
   0.25. The third draw's [A2] failure (null 0.391 against chance 0.5) is
   the same draw noise.
5. **Stamped values are kept as if decided.** apply-screen committed the
   stamp's `margin = 0.25` and `null_band = 0.1` under a [C1] sentence
   that named neither ("exceeds 0.5 (chance)"), although the comment above
   the tables says they are the stamp's examples; it ran
   `--calibrate-null` only after its first measurement (0.1295) and then
   changed both — the move fault 1 and 2 describe. fit-assay kept the
   skeleton's `SCORE = "accuracy"` for a task that asks for ROC-AUC; the
   probe's meaning check names it. The hint about the template's example
   values was not heeded in this draw (TODO item 12's open question).
6. **An audit outlasts the agent's 120 s command limit.** Claude Code
   moved apply-screen's analysis audits to the background twice; the
   agent polled with `sleep` (`ps` is missing in the image). Known (TODO,
   "Auditdauer"); cost, not a wrong result.
