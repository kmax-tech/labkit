## 3. Three Biggest Time Sinks

### 1. Audit Loop: Understanding and Satisfying Labkit Requirements (~70 minutes)
**Cause:** The lab standard requires multi-layered audits with decision reviews before adoption. Each code fix triggered new audits that found new issues:
- Initial audit found standardization bug (divide by variance not std)
- Fix required declaring model.json as a dependency
- New run required new audit
- Audit found WARNINGs requiring decision reviews (2 rounds of review)
- Added probability output required another measurement and audit loop
- Protocol declaring wrong run required another audit cycle

The process involves: measure → finalize → audit → decide findings → review decisions → re-audit follow-ups → commit records → attempt adoption → fix protocol → repeat.

### 2. Decision Reviews and Null Band Verification (~40 minutes)
**Cause:** The reviewers questioned whether [A2] (null admissibility condition) properly anchored the predictor, requiring:
- Rewriting the Conclusion to acknowledge A2 checks permutation, not predictor output
- Running `--calibrate-null` to supply evidence that null_band 0.13 is appropriate
- Making two rounds of decisions and reviews before both were upheld

### 3. Adding Probability Output (~25 minutes)
**Cause:** The task requires saving predicted probabilities to CSV, but the initial measurement stored only predictions (referral/no_referral). Adding probability output required:
- Modifying ScreeningModel to add `predict_with_prob()` method
- Updating `apply_rows()` and `lane_row()` functions to capture and store probabilities
- Changing output filename (`_v2.jsonl` → `_v3.jsonl`) to mark the code change
- Running full measurement, finalization, and audit cycle again
- Resolving the protocol declaring the wrong run (5581 vs 90d9)

## 4. What I Had to Guess

1. **Standard Deviation vs Variance:** The model.json field `"std"` could have meant either. I verified by checking the values against known domain knowledge (age sd ~12 years is reasonable; variance of 12 years² is implausible) and the audit confirmed the interpretation was correct.

2. **Null Band Recalibration:** The warning said the null_band 0.13 was pre-computed before the fix. I had to run `--calibrate-null` to provide evidence it was still valid. The recalibrated band 0.1276 confirmed the registered band was appropriate.

3. **Output File Naming:** The measurement script comment said "a new measurement gets a new file name". I inferred this meant `_v2.jsonl`, then `_v3.jsonl` after adding probabilities, based on convention. The runlog warning confirmed this was correct.

4. **Decision Review Requirements:** The adoption refused until decision reviews were obtained. I had to understand that "rejected" vs "upheld" status determined whether the number could be reported, and that changes to the Conclusion after decisions required re-review.
