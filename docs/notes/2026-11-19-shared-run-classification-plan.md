# Shared run classification: a bounded plan (f2820d23, 2026-11-19)

> Plan, not commissioned; decided by the author 2026-11-19: classification and reasons shared, messages stay per entry point.
>
> State 2026-11-19, later the same day: both contradictions named below are repaired by reuse, without a new layer. The report duty reads `WithoutRecord` (d56cc46b). The handover asks `Measured.may_have_measured` (2e1b893d), as the author decided: a run whose readable start file names it a probe or a preparation is no possible measurement; with the kind unknown it still counts. The line numbers below are those of 79a42aff. Open question 1 at the end is answered by that decision.

The [audit of 2026-11-19](2026-11-19-repo-audit.md) proposed one function that turns what an area measured into the findings every entry point tells (its open point 3). The author declined that and narrowed the goal: one place decides how a run is classified and why; each entry point keeps its own sentences. This note lists where a classification is decided twice today, which differences between the entry points are meant, and the smallest step per real contradiction. Nothing here is built.

Terms. An **entry point** is a command or hook that tells a person about a run: `finalize` (its registration station), `report-check` (its report-duty station), the run start (`runlog`), the post-change hook, and the handover (`protocol-fill --handover` and the check that a handover still stands). A **classification** is the class a run falls into for one protocol, with its reason: measurement or not; for a run without a record, "may have been the first measurement", "order unknown", "started later" or "assigned to no protocol". A **run without a record** is a run only the run index lists, a run only a start file names, or a run whose `config.json` does not read.

Sources. **C** marks a statement read from the code at the lines named, at commit f2820d23 with no tracked change in the tree. **R** marks a statement taken from the audit's homes reader (its report lay in a session scratchpad and is not kept) and not opened again. No command was run for sections 1 to 3: every case is read from code, not replayed.

## 3. Which contradiction a merge would prevent

**May have been the first measurement — constructed case.** Protocol P registers no report, at its first measurement and now. Run A is a readable, committed measurement with a start file at 10:00. Run B is a measurement with a start file at 11:00; it completed, the run index lists it, and its directory was deleted before a commit. finalize sorts B as "later": no hold (`labkit/gates/registration_hold.py:919`-`:921`) and a warning that "the comparison with the first measurement runs without it" (`:963`-`:972`). The run start says of B "nothing is held for it" (`labkit/run/start_check.py:274`-`:280`). report-check's duty station returns "a measurement of it is lost" (`labkit/gates/registered_report.py:482`-`:490`) and blocks with "whether it owes a report cannot be told" (`:562`-`:573`). One run, one state: "later, nothing held" at two entry points and "may have been the first, held" at the third. (C, not replayed. Another agent is repairing this.)

**May have measured — constructed case.** Protocol P was handed over. Afterwards a probe starts under P; its start file says `run_kind = "probe"`, and its `config.json` is later damaged. `handovers.runs_since` counts it (`labkit/formats/handovers.py:815`), so the handover no longer stands: "run R was measured after the handover … a new handover binds it" (`:780`-`:785`). A new handover records "a run was measured, and its record gives no number" (`labkit/gates/report_check.py:1054`, `labkit/formats/handovers.py:108`). For every reader of `has_measured` the same run measured nothing: `labkit-next` still adds the hint for a protocol before its first measurement (`labkit/gates/next_step.py:678`), and the run start holds the next run to HEAD as the first measurement (`labkit/run/start_check.py:177`-`:180`). (C, not replayed.) A message-only twin: a lost probe that the run index lists is told by the hook as "runs.tsv lists it as measured" (`labkit/gates/hook_post_change.py:149`-`:151`); finalize does not count it.

**Has the area measured — none found.** The copy at the run start cannot differ in verdict today. It would differ after an edit that adds a source to one side only.

**Readable measurement that is no repeat — none found.** Both spellings read the same runs.

**Unlistable history — constructed case, not a doubled decision.** An object of the repository is missing, so git cannot list the runs or start files a commit holds. The hook prints git's words. finalize prints nothing about it, and its missing-start hold cannot fire because the list it reads is left empty. (C for both paths, not replayed; audit open point 1, under repair.)

Sum: four doubled decisions, two of them with a constructible contradiction, plus one reason that only one entry point can read.

## 4. The smallest step per real contradiction

1. **May have been the first measurement.** `report_duty` reads `WithoutRecord` (through `registration_hold.without_record_of`, which already handles a state of git's index) and is undetermined only for its `held` runs. A "later" run gets the existing warning. This deletes the enumeration at `labkit/gates/registered_report.py:468`-`:490` and adds no layer. Twin test: the case of section 3 gives no duty blocker; the existing test at `tests/test_registration_committed.py:1912` still blocks. Under repair by another agent; this plan adds nothing to it.
2. **May have measured.** Three call sites ask `measured.may_have_measured(rd)` in place of `is_measurement(rd)`: `labkit/gates/report_check.py:1054`, `:1063` and `labkit/formats/handovers.py:815`. The typing protocol `handovers.PresentRuns` gains that one method. The hook's sentence at `labkit/gates/hook_post_change.py:149` says "finished" for "measured", or names the kind from the start file as its neighbour at `:155` does. Twin test: an unreadable probe after a handover leaves the handover standing; an unreadable record without a start file still ends it. This changes when a handover stops standing, so it is the author's decision (open point 1 below).
3. **Unlistable history.** Under repair. For this plan only the direction matters: the reason travels with what the entry points already read (`Measured`), so the hold can state it; no entry point computes it again.

Two cleanups remove a copy without changing behaviour. They are optional and each is one commit: `labkit/run/start_check.py:177`-`:180` becomes `if measured.has_measured: return []`; and the predicate "readable measurement, no repeat" gets one named function in `answering_run` that both sites call.

## 5. Not proposed

- No function that returns every entry point's findings from `Measured` (audit open point 3). None of the three contradictions comes from a message list; two come from a classification decided again, one from a reason not carried.
- No table of condition, sentence, way back and severity in place of the hold functions in `registration_hold`.
- No merge of sentences: the run start's own sentences (`labkit/run/start_check.py:262`-`:295`, C), the hook's (`labkit/gates/hook_post_change.py:142`-`:180`, C), the variants of "bring the record back" and of "restore the repository's missing objects" (R, findings 10 and 13 of the homes reader) stay per entry point.
- No change to who holds and who warns (section 2, the rows marked intended).
- No hook line for a contradicted binding. It is a stated open limit and a decision of its own.
- No renames on `Measured` and `AreaState` (audit open point 5).

## 6. What evidence would justify more

1. **A replay.** Sections 1 to 3 are read from code. The three cases can be built in memory with `area_state.assemble`, as `tests/test_first_measurement_hint.py:197`-`:228` does. A case that does not replay removes its step from this plan.
2. **A matrix test instead of a merge.** One table-driven test states, per condition of a run, what each entry point does: holds, warns, or says nothing. It pins the intended rows of section 2 without touching a sentence. If that test goes red on a later change, the per-entry-point lists have produced a verdict error; that is the evidence a shared findings function lacks today (count so far: 0).
3. **The next new condition.** The missing start file took changes in seven modules (R). Count the modules for the next condition and whether an entry point was missed. One miss that changes a verdict justifies more than this plan; a miss that changes a sentence does not.
4. **A reader misled by two sentences.** A task log in which an agent or a person acted wrongly because two entry points worded one state differently would justify a shared sentence for that state, and only for it.
