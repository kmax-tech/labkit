# Explicit run kinds — 2026-10-20

## Problem

`long` named a duration but declared whether an execution was a full run.
At seconds, `every_run_full` applied measurement start obligations even
when the script declared `long=False`. The record still called it a
probe, and reporting refused its number. Start checks and recorded purpose
therefore described the same execution differently.

## Decision

The script declares `run_kind="probe"` or `run_kind="measurement"`.
The former checks the instrument; the latter measures the registered
question. At seconds the complete measurement is cheap to repeat and
serves as its own instrument check, so a separate probe is refused.
Minutes/hours retains the probe stage. Measurement status does not release
a result: audits, completion and recomputation remain separate obligations.

Schema 3 carries the string, validated at the API and file boundaries.
The old argument and record field have no compatibility path. The last
release that reads the old format is 0.99.0. The default purpose remains a
probe so an omitted argument cannot silently start a full measurement.

Data preparation already has its own run record in `00_prepare.py`. It
is neither an instrument probe nor the registered measurement; the
additional kind `"preparation"` preserves its provenance without making
its metrics reportable or requiring a freeze before preparing inputs.
