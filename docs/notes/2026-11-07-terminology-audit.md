## Corrections at the source

These factual corrections were made in the lab standard itself, the source of the rule text, against the current implementation. They change neither the decision rules nor the release conditions.

1. `labkit/docs/standard.md:117` said a limitation writes a note in Conclusion and report-check binds both to the record. `labkit/checks/result_render.py`, `rendering`, appends `findings.answer_note` to Recorded results; `labkit/tools/protocol_result.py`, `from_run`, explicitly leaves Conclusion to the author. The standard now names Recorded results here.
2. `labkit/docs/standard.md:316` used `dismissed` in its current analysis-audit example. The current statuses in `labkit/formats/findings.py`, `STATUSES`, include `false-positive` instead. The example now uses the current name and a reason showing counter-evidence.
3. `labkit/docs/standard.md:310` offered “subagent or labkit-audit” for the analysis audit. The same standard's preflight rule says the harness subagent copy is no second route (`labkit/docs/standard.md:115`), and `labkit/gates/audit.py` identifies the command as the only runner. The analysis rule now refers to the shipped command consistently.

## Boundaries that remain distinct

The adopted run is the answering run once an adoption exists; before adoption, answering-run selection chooses among eligible runs. This is intentional, not competing definitions (`docs/protocol-run-binding.md`, “The answering run”; `formats/answering_run.py`).

A per-promise declared-scope hash and the area's audit stamp cover different scopes. The contracts explicitly distinguish them (`docs/promise-block.md`, “What the declared-scope hash states”; `formats/scope_sha.py`). No rename is proposed here.

Finding subjects, person decisions, follow-up verdicts and decision-review verdicts are different dimensions. README now names each dimension and its owner. A report review stores `ReportClaim` records of kind `result` or `contradiction`, rather than ordinary audit findings; “finding” in its prose is descriptive, not the `findings.Finding` schema.
