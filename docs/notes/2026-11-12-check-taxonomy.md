# A taxonomy of the checks — first bounded version, 2026-11-12

*What labkit's gate findings test, per cause: the objects a condition reads, each with its role and version, and the property or relation it tests. This is a first version with a stated reach: 199 of 299 rows carry one property, 100 are shown as open. It is a usable working classification, not a settled one, and it says nothing on whether a check works correctly. How it came about, with every earlier schema and reading, is in [the full pass](2026-11-11-check-classification-full.md).*

## The definitions in force

`docs/notes/2026-11-12-subject-readings/object-property-definitions-4.md` is their one home: nine objects, the roles by property, the versions, ten properties and nine rules. In short:

- **Objects:** protocol, run record, area code, area checks, audit and review records, generated block or line, report, text beside the protocol, repository and working state.
- **Versions:** as it stands (said as the working tree or the index where the two are compared), as a commit holds it, as a run recorded it, rebuilt (from a run's commit and its patch).
- **Properties:** completeness, readability, form, uniqueness, inner consistency, agreement, binding, audit coverage, order in time, result of an executed area check.
- **Apart from the property:** how a row is cut (one condition, aggregated, mixed, joined, open), and a limit of the execution, which belongs to the check's outcome.

The classification follows the condition the code tests and what it compares — not the way out, not the wording of the message, and not which side of a comparison is to blame.

The share is the reach over the rows as this table cuts them. It is not a share of checks that work, and not of causes: a bundle counts as one row and holds two to ten conditions.

The properties of the 199 rows: completeness 70, agreement 48, audit coverage 23, readability 16, binding 11, inner consistency 11, uniqueness 8, form 6, result of an executed area check 5, order in time 1.

**Where an entry comes from.** The column "Reading" says it per row.

- The two readers read every row at the code on 2026-11-12, independent of each other and of every earlier answer, under the third version of the definitions (`object-property-definitions-3.md`). Their answers and the comparison per row: `docs/notes/2026-11-12-subject-readings/object-stock-1-reader-A-part-NN.json`, `-B-part-NN.json`, `object-stock-1-compared.json`. They are readers of the same kind with the same definitions; no row was checked by a third party.
- The fourth version changed three things after that reading: a thing that is not there is completeness, a technical failure is a limit of the execution, and a bundle is a statement on the row's cut. The 37 entries this touches were read again at the code by one reader of this session (36 of them listed in `object-stock-1-fourth-version-changes.json`; the last, `code_check.quality_check_reads`, by the author's ruling). The two readers' agreement does not confirm these 37. Missing is not completeness by itself: where the missing thing is only the technical precondition of another check (no git repository), the entry is a limit of the execution, and seven entries say that this was not told apart.
- The 165 entries left as the readers gave them were not read again under the fourth version. They were checked only for the three changes above; the nine rules of the fourth version were not applied to them one by one.

## What is open

1. **46 bundles.** Left as a stated limit by the author's word. One is resolved only where a concrete technical or methodical decision follows from it. The readers list about 190 conditions behind them, not checked; three kinds return (the cause is carried as data, a helper with a closed list of raises, a strict reader with many raises).
2. **24 rows the readers do not agree on,** 14 of them because one reader calls the row a bundle.
3. **15 rows no value fits.** Described in five kinds, which are no categories: a mark or file that records a state (5), something that stands in the text or the code (6), how git holds a file (2), two things that are the same (1), two states combined (1). No value is added until one holds a clearly defined statement that returns.
4. **13 rows without a property by this session's reading:** six mixed units, seven limits of the execution.
5. **A rest without a category:** a reference to itself and a circle of references (two rows). Things read that are in no object of the list — a run's input data, a model profile, the area as such — are named in plain words where they occur; what is open is their place in the list of objects, not what they are.
6. **Five rows with joined conditions** (the finding is told only when two conditions hold together) are marked as such; the conditions are not classified one by one yet.

New rounds of readers are for a concrete disputed question, not for the whole table again.
