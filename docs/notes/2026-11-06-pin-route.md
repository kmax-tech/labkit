# Pin route: the run record pins a source outside git

2026-11-06. Draft for decision (b) of 2026-11-05 ([One explainer](2026-11-04-one-explainer-plan.md), "Decided 2026-11-05"); no code changed. Baseline `76757ed9`. Building waits for the author's go on this draft.

## Problem

A source the run read that git does not track blocks `finalize` (station 5, `check_provenance`) unless one of three routes pins it. Each route is a format the agent can get wrong:

1. **Tracked in git** — right for small inputs that may legally be shared, impossible for a model directory of several hundred megabytes.
2. **Its checksum in Data / scope** (`run_record_check.pinned_source`) — the agent learns the checksum only after the run, and writing it into Data / scope then is a change to a registered field after the first measurement, which the registration hold refuses (area 19's finding).
3. **A tracked `MANIFEST.sha256` at or above the source** (`_source_manifests`, `_manifest_finding`, `formats/data_manifest.py`) — a third format; a manifest written inside the source directory changes the directory's digest, so the run no longer matches its own record (tsts512-r1).

Evidence: in area 23 of labkit-paper the first hold of all three sts512 attempts was the model directory `benchmark/models/all-MiniLM-L6-v2`, untracked and excluded by the sandbox repo's `.git/info/exclude`; none of the three found a route, all three handed over without a number. Area 21's adopted sts512 agents wrote a manifest.

## Decided (2026-11-05)

One route: the run's own record. `runlog.run(..., data={...})` already writes the sha256 of every source it read into the record; the record is committed, git holds it, and `finalize` compares the bytes now with it. The checksum in Data / scope and the manifest go (Breaking). Two duties stay apart: the checksum is the record's; how to get the data back (source or access route, version) stays prose in Data / scope, as the standard's Fixed inputs say — a hash alone brings no data back.

The standard needs no change: Fixed inputs already says "the repository holds instead their source or access route, version and checksum (the run records each read file's checksum, `data=`)" (`labkit/docs/standard.md:126`).

## Change

In `run_record_check._source_finding`, for a source with untracked files:

| Case | Today | After |
|---|---|---|
| Recorded sha, bytes match, sha in Data / scope | pinned | pinned |
| Recorded sha, bytes match, sha not in Data / scope, no manifest | blocker | pinned (subject to open decision 1) |
| Recorded sha, bytes differ | blocker | blocker, unchanged wording: restore the bytes or measure anew |
| No recorded sha (`data=` missing the source) | blocker | blocker: pass the source in `data=` and measure again |
| Named in a tracked manifest | pinned or blocker per line | manifest not read |

The pinned note names the route: "source X lies outside git, pinned by the checksum the run recorded (sha256 …)". The blocker for an untracked source without a recorded sha keeps its first way out (commit it if small and shareable, `git add -f` past an ignore rule) and drops the two pin formats.

What the guaranteed tier then states: the bytes the number came from are the bytes on disk now, checked against a committed record. What it does not state: that someone else can get those bytes back. That stays with Data / scope's prose and the agent audit, as it already is for the route and version today.

## Tests and probe

Twins in `tests/test_finalize_provenance.py`, each seen red on the old code where it changes behaviour:

- an untracked source with a recorded sha and unchanged bytes, Data / scope without the sha, passes (red today);
- the same source with one byte changed blocks;
- a source missing from `data=` blocks with "pass it in `data=`";
- a `MANIFEST.sha256` beside an untracked file without a recorded sha pins nothing (the manifest is not read);
- with open decision 1 taken as recommended: an untracked file no ignore rule covers blocks with "commit it, or ignore it on purpose", its twin under `.git/info/exclude` passes.

Probe: a case in the repair-path probe (`labkit-evidence`, `run-all.sh`) with an sts512-like model directory excluded by `.git/info/exclude`: measure, adopt, commit — no hold on provenance, and the record and report go in one commit.

## Check before building

1. **The record must be committed.** The route rests on "the record is committed". The 2026-11-05 decision says the commit holds until the record comes with it (fix 1, `12ee8eb6`); that has not been reproduced for this case. Before building: stage a report citing a run whose `runs/<id>/` is untracked and see whether the commit holds. If it does not, that hold is part of this step.
2. **A directory source's digest covers every visible file.** Any file added under the model directory after the run (a README, a cache) changes the digest and blocks with "restore or measure anew". The manifest route had the same limit (tsts512-r1); the hold's wording should name the added file where the record allows it, else this stays a known limit in the field guide.

## Open decisions

1. **Untracked without an ignore rule: pin or block?** (a) Every untracked source whose bytes match the record passes — the simplest form, as decided. (b) Only a source git ignores passes (`.gitignore`, `.git/info/exclude`; `_ignore_rules` exists); an untracked file no rule covers blocks with "commit it, or ignore it on purpose". Recommended: (b). Under (a) a small CSV the agent forgot to `git add` passes silently, and the standard's "small inputs that may legally be shared are committed" loses its only mechanical check; under (b) keeping data outside is a visible act. sts512 passes under both (its directory is excluded).
2. **Release order.** Build after 0.112.0 so that the Breaking entries of the two releases stay apart; the next usage round needs both tags pushed.
