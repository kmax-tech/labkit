What a look at the code and the standard adds to four of these (2026-11-11, after the feedback the author passed on; nothing was entered for it — a nearest sentence closes no assignment):

- **The notes' schema.** LAB-082 says "schema above", and the shipped standard holds no schema of the meta line: it names the meta line at LAB-082, at the sketch-or-settled axis and at LAB-100 Answer before reasoning ("the purpose in the meta line"), nowhere its parts. The author's house rules hold one (`<purpose> · <kind> · reference · <date>`), outside this repo. So the date has a source a lab with labkit alone cannot read; the two other conventions (named scripts resolve, `related-*` matches its kind) have none.
- **No `outputs.json`.** Four checks read the file and treat its absence as "no output registered" (`output_record_findings`, the row provenance, the audit binding, `recheck`). The warning is the one place that says so. It states that these checks had nothing to hold, a missing basis — not that a run owes an output.
- **An output not in git.** No check needs it; it is a duty of keeping (the fix says "before the commit that cites the number").
- **The registered report.** The duty does not start with the file: a report draft before the first measurement owes nothing, and after one a progress account passes (`registered_report.report_owed`). What is held is a written report once a measurement or an adoption exists, without the result block, the handover block or the account.

### Decided 2026-11-11: registration (5)

1. **The freeze at the report** (`labkit/gates/report_check.py:267`): a wanted duty, as far as the same measurement already owed the freeze before its run. The sentence that states it must say so, and a `frozen = true` set afterwards must not make a run reportable that started without the freeze it owed. The code holds both halves apart already: the run records the acknowledgement of an unfrozen start and is unreportable by it, whatever the head says now (`runs.unreportable`), and this site reads the head as it is now, so it holds a flag that is missing after the run. The author released the wording the same day; it stands in LAB-104 (`labkit/docs/standard.md`, after the list of what an adopted number owes, in the unreleased standard 0.27), and the site records LAB-104 (251a45cd).
2. **A successor is exploratory** (`labkit/gates/report_replacement.py:83`): the blanket ban is too wide. A successor may be confirmatory on data not yet evaluated for the changed question, when its registration is complete in time; "new data" alone is not enough. Equal checksums prove equal bytes and nothing about whether the data were evaluated for the changed question or chosen by the result, and other checksums can hold the same observations reformatted. So the comparison of checksums gives an exact finding on data identity and decides neither "exploratory" nor "confirmatory"; the classification needs the audit. The check is marked for a targeted change (its own step, with the agent guide's instruction `type = "exploratory"`); the assignment stays open until then.
3. **Every difference is declared** and 4. **every declared change exists** (`labkit/gates/report_replacement.py:186`, `:199`): technical contract of a documented format convention, entered (37efe001). The contract reaches the registration fields labkit compares (`protocol_history.registration_differences`), which `labkit/docs/agent-guide.md` now names. Whether a change's reason suffices as method is another question and stays open (the cause "a `[[replaces.change]]` without its reason").
5. **The report target** (`labkit/gates/registered_report.py:334`): moving the entry and entering it late are to be allowed; the duty to report that a measurement took on must survive. Holding only the removal of the field is not enough: a rename or a successor protocol must not remove that duty unnoticed either. The build step therefore states how a new target replaces the old one explicitly, and starts with a test that reproduces rename and successor — what happens there today is not checked. The assignment stays open until then.
