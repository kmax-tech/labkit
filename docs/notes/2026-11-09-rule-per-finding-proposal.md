# Which rule each finding holds — proposal for 2026-11-09

*Proposal · for the author to decide row by row; line numbers at ffde5838; standard 0.27 (LAB-104 split off LAB-011 Required-field check)*

Of the 201 finding sites that cite no rule ([check inventory](2026-11-09-checks-have-no-switches.md), `just inventory`), 150 get a proposed rule and 51 hold no rule of the standard. With the proposal taken, 26 of the 97 active rules are held by at least one finding (today 10); the other 71 are held by an agent audit, by the author, or by nobody — they are the candidates the measurement asks about.

## Limits

- "No finding would hold it" is about finding sites. A rule can still be held without one: by a helper's design (`LAB-064 The pilot is resumable too` — `batch.Store` resumes), or by a `console.Refused`, which the inventory leaves out as "the command cannot run".
- `LAB-069 No LLM cache` said the lab keeps no cache while labkit shipped one (`labkit/run/llm_cache.py`). Settled in standard 0.27: LAB-069 No LLM cache unless the lab declares one; the cache opens where `models.toml` says `[llm_cache] enabled = true`.
- The proposal reads each site's wording and the standard's rule texts, not every check's code; "sure" means the rule's text names the hold, not that the check was read line by line.

## How to read it

| Confidence | Meaning                                                        |
|------------|----------------------------------------------------------------|
| sure       | the rule's text names what the check holds                     |
| likely     | the rule's purpose covers the check, its text does not name it |
| unsure     | a guess; another rule may fit better                           |

| Class without a rule | Meaning                                                                                                                        |
|----------------------|--------------------------------------------------------------------------------------------------------------------------------|
| unavailable          | the check cannot read its input or cannot run, and blocks because it cannot judge — a house principle, no rule of the standard |
| mechanical           | a precondition of the check itself (index against tree, an adoption cut off, a symbolic link)                                  |
| pass-through         | the message is built elsewhere; the rule belongs where it is built                                                             |
| usage                | a wrong command line                                                                                                           |
| not-lab              | a developer probe, no lab check                                                                                                |
