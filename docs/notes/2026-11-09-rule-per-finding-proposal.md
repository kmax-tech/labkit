## Limits

- "No finding would hold it" is about finding sites. A rule can still be held without one: by a helper's design (`LAB-064 The pilot is resumable too` — `batch.Store` resumes), or by a `console.Refused`, which the inventory leaves out as "the command cannot run".
- `LAB-069 No LLM cache` said the lab keeps no cache while labkit shipped one (`labkit/run/llm_cache.py`). Settled in standard 0.27: LAB-069 No LLM cache unless the lab declares one; the cache opens where `models.toml` says `[llm_cache] enabled = true`.
- The proposal reads each site's wording and the standard's rule texts; the review read the code of the rows it names. "sure" means the rule's text names the hold, not that the check was read line by line.

## How to read it

| Class        | Meaning                                                                                                     | Rule column                                       |
|--------------|-------------------------------------------------------------------------------------------------------------|---------------------------------------------------|
| violation    | the finding says a rule is broken                                                                           | the rule broken                                   |
| unavailable  | the check cannot read its input or cannot run, and blocks because it cannot judge — no rule is shown broken | the rule whose check could not run; counted apart |
| pass-through | the message is built elsewhere; the rule belongs where it is built                                          | —                                                 |
| mechanical   | a precondition of the check itself (index against tree, an adoption cut off, a symbolic link)               | —                                                 |
| usage        | a wrong command line                                                                                        | —                                                 |
| not-lab      | a developer probe, no lab check                                                                             | —                                                 |

| Confidence | Meaning                                                        |
|------------|----------------------------------------------------------------|
| sure       | the rule's text names what the check holds                     |
| likely     | the rule's purpose covers the check, its text does not name it |
| unsure     | a guess; another rule may fit better                           |

Where several rules fit, the row takes the one whose text names the hold.

## Review 2026-11-09

Four points checked at the code; each row they change is marked `R` in the table below.

1. **A check that could not run is no violation.** `labkit/checks/code_check.py:387` reports that the quality-check read check stopped on an error; `labkit/checks/prompt_check.py:216` that a prompt expression cannot be computed statically — a valid dynamic prompt warns too. Both are `unavailable`, keeping the rule their check holds. The same holds for every unavailable row: it names its rule and is counted apart.
2. **Data sources fall under the general freezing rule.** `labkit/checks/run_record_check.py:570` compares every source given as `data=`, inside the repository or not, not only `data/prepared/`; LAB-041 Generate numbers, don't retype them says "Freeze data sources via `runlog.run(..., data={...})`" (`labkit/docs/standard.md:288`). Its neighbour `:527` (a run that froze no source) takes the same rule. LAB-058 `data/prepared/` is read-only after writing stays for a finding that shows a change to prepared data.
3. **The adoption rule where its text names the hold.** LAB-104 A number leaves the area only through its adoption: it requires that a report's result blocks show the run the protocol adopted and equal its rendering, and that every cited run id names a run of the repo. So `labkit/checks/report_blocks.py:283`, `:293`, `:301`, `:310`, `:359`, `:367` and `labkit/gates/report_hold.py:508` take LAB-104 A number leaves the area only through its adoption, not LAB-041 Generate numbers, don't retype them or LAB-043 Runs go through `runlog`.
4. **A forwarded message gets the rule of its cause.** The recomputation (`02_analyze.py --check`, `labkit/checks/recheck.py`) forwards different causes: `:72` a protocol head that does not parse and `:96` a run config that does not parse (unavailable), `:83` the reason a run was not chosen (pass-through), `:168` a promise block that does not parse (unavailable), `:171` promises changed since the run (LAB-003 No run without an intent paragraph), `:145` a declared scope changed since the run (LAB-103 The audit reads by declared scope, not by import graph, as finalize's same check). A message of the form `{exc}`, `{gap}` or `{why}` gets a rule only after its causes are read.
