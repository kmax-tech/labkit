## Summary

The merged state names standard 0.32, and that text comes from `main` alone; the branch changed what a protocol owes and what holds a number without changing the standard. This note finds 15 changes whose content the author has already decided (section A). Of the 8 questions the first draft listed, the author answered all on 2026-11-19 (section B): five confirm the draft or an earlier decision, two change the proposed text (B3, B5), one added a build task before the version step (B7), built on 2026-11-19 with its text proposed there; the replay for B6 led to a gate change the author decided the same day. The decided changes touch nine rules and three glossary entries: LAB-003, LAB-004, LAB-011, LAB-015, LAB-017, LAB-041, LAB-043, LAB-050 and LAB-104. Run record schema 5 itself is a record-format change and needs no standard sentence, but the start duty and the release hold built on it are standard changes, for the reason the author gave for 0.32. Four of the branch's changes — `[kept]` at every kind, the optional criterion, the owed type and the split of the registration locks — have no entry under "Unreleased" in `CHANGELOG.md` yet; the version step has to write it.

Terms used below, each once. A *first measurement* is a run at the earliest commit at which the protocol was measured (`labkit/formats/answering_run.py:402`). The *answering run* is the run a protocol's number comes from. A run's *own text* is the protocol as that run started under it: its recorded commit plus its `uncommitted.patch`. A *step* is the `[builds_on]` table in the protocol head: the change the next runs make against a named earlier run, the *basis*. An *origin run* is the run of the same area that wrote a file a later run reads as input. The *adoption* is `labkit-adopt` writing `[result] run` into the protocol. A *hold* is a blocker that keeps a number from being adopted, committed or reported. The *workflow* is which of two sets of holds binds a protocol's runs: confirmation or exploration.

### Run record schema 5: record format or standard change

Both, split at one line. The number `schema_version = 5` and the fields `origin_run`, `origin_chosen` and `origin_unreadable_runs` are a record format: the standard names no schema version and no record field of `config.json` (`grep -c 'schema_version' labkit/docs/standard.md` gives 0; the same grep finds `start file` on 6 lines, so it can find a term that is there). They belong in `CHANGELOG.md` under "Breaking" and nowhere in the standard. What the format carries is a standard change: a duty at the start (a script names the origin where several runs wrote the same bytes, else the run does not start) and a release hold (a computed number is not released while an origin run, its registered output, or the protocol text it started under does not read back). That is the ground on which the author made the start file version 0.32 on 2026-11-18: "add a duty and a release rule the standard did not state" (`CHANGELOG.md:9`). The gates cite these holds as a technical contract today (`labkit/checks/origin_check.py:210`), as they do the start-file holds that 0.32 states (`labkit/gates/registration_hold.py:873`, `:906`), so the code's citation does not settle the question. If the author strikes the proposed paragraph (A11 below), no gate changes; the standard then stays silent about a hold that blocks an adoption.

### Proposed text, by rule

Each entry quotes the 0.32 sentence and says whether it becomes wrong or incomplete. Proposed text is marked "Proposed"; it follows the standard's style and names no date or incident.

#### Version line (`labkit/docs/standard.md:3`)

Now: `*Version 0.32 — the version a protocol names in its head (`standard = "0.32"`, read by `protocol_block`).` The line needs the new number in both places and one clause for 0.33 before the clause for 0.32.

Proposed: "0.33 (<date>): every kind names the number it reports in the head's `[kept]` table, and a fit's or an apply's criterion judges exactly that number (LAB-004 Identifiers make the intent addressable); the criterion is owed in confirmation and optional in exploration; the `type` is stated before the first measurement, without it no measurement starts, and it stays as that measurement registered it; an exploratory protocol holds each run to the protocol text it started under and to the step it declares on a named earlier run (`[builds_on]`), while a confirmatory protocol stays held to its first measurement (LAB-003 No run without an intent paragraph); a run records for each input the run of the area that wrote those bytes, where there is one, and a number computed from such an input is released only while that run, its output and its protocol text read back (LAB-043 Runs go through `runlog`); the recomputation is made per protocol and with the code the run ran (LAB-041 Generate numbers, don't retype them); a measurement protocol whose runs are reported through another protocol's adopted analysis says so in its registered report (LAB-104 A number leaves the area only through its adoption); under 0.32 a fit or an apply reported its number through its criterion's keys, and every protocol was held to its first measurement."

#### Glossary "Freezing (frozen)" (`:46`), A15

Now: "**Freezing (frozen)** — fixing hypothesis and criteria in writing; from then on the run counts as a test, before that it is exploration." Wrong: an exploratory protocol at high repeat cost is frozen too and stays exploration.

Proposed: "**Freezing (frozen)** — declaring the registration and the instrument ready for a run that is costly to repeat (`frozen = true`, after the instrument check and the preflight audit). Whether a run tests or explores is its protocol's `type`, not the freeze."

#### Glossary "Confirmatory / exploratory" (`:47`), A2 to A4

Now: "confirmatory: the question, the inputs and the analysis plan stood before the relevant results were seen; a fit or an apply also fixes the success criterion it is judged by, while a computation needs none — its plan is the quantity, unit and exclusions. Otherwise exploratory: the approach is formed or chosen with what was already seen. The two types cover a computation too; there is no third." Incomplete: it does not say when the type is stated or that it selects the holds.

Proposed, appended: "The type is stated before the first measurement, at every kind and repeat cost, and it decides which holds bind the protocol's runs (LAB-003 No run without an intent paragraph). A protocol without a stated type is incomplete: no measurement starts under it."

#### Glossary "Head" (`:60`), A1 and A5

Now: "**Head** — the TOML block of the protocol (`[protocol]`: `standard`, `id`, `type`, `repeat_cost`, `frozen`, `preflight_audit`): the fields that a machine reads, as data instead of prose; plus the `[[promise]]` tables." Incomplete: `kind` is missing already at 0.32, and `[kept]` and `[builds_on]` are head tables.

Proposed: "**Head** — the TOML block of the protocol (`[protocol]`: `standard`, `id`, `type`, `repeat_cost`, `kind`, `frozen`, `preflight_audit`): the fields that a machine reads, as data instead of prose; plus `[kept]`, the key and unit of the number the protocol reports, the `[[promise]]` tables, a computation's `[reference]`, and in exploration the step `[builds_on]`."

A new glossary entry is needed for the step. Proposed: "**Step** — in an exploratory protocol, the change the next run or runs make against a named earlier run, the basis: the head's `[builds_on]` table with a name (`id`), the basis `run`, the `occasion` (`observation`, `planned` or `repair`), the reason (`why`) and one row per changed part of the registration. `protocol-fill <PROTOCOL> --builds-on <run_id>` writes it and computes the rows from the two texts; what counts is that the rows equal the differences, which the release checks, not who wrote them."

#### LAB-003 No run without an intent paragraph (`:71`–`:75`), A2 to A7

Sentence 1, now: "before every experiment, 5 lines — hypothesis, success criterion, quality check — as `PROTOCOL-<task>.md` next to the script, if need be in the docstring." Wrong for an exploratory fit or apply, which owes no success criterion; incomplete for the type.

Proposed: "before every experiment, 5 lines — hypothesis, the type (exploratory or confirmatory), the quality check, and in confirmation the success criterion — as `PROTOCOL-<task>.md` next to the script, if need be in the docstring."

Sentence 2, now (`:73`): "What stood is what the commit of the first measurement holds." Incomplete (A7): a run started from a changed tree stood under its commit plus its patch.

Proposed: "What stood is the protocol as the first measurement started under it: its commit and, where it started from a changed tree, its `uncommitted.patch`. Where that patch is lost, the text cannot be read back and the commit alone does not stand in for it."

Sentence 3, now (`:73`): "The question stays as registered, a typo included, and so does a promise's sentence, key or constant: the registration check holds every change to them and cannot tell a typo from a new choice." Wrong as a general statement (A6): it holds in confirmation only.

Proposed: "In a confirmatory protocol the question stays as registered, a typo included, and so does a promise's sentence, key or constant: the registration check holds every change to them and cannot tell a typo from a new choice."

New paragraph after "Incomplete at the first measurement", proposed (A3, A4):

"**The type decides the workflow.** The type is stated before the first measurement; a protocol without it is incomplete, and no measurement starts under it. Which holds bind a protocol's runs follows from the type its first measurements registered, read from the protocol as those runs started under it, never from the head as it stands. A type changed after the first measurement is held in either direction: relabelling lifts no confirmatory hold and turns no exploration into a confirmation. The way on is the type put back, with a new measurement where a run measured under the change, or a new protocol of the other type; the earlier runs and their findings stay. First measurements that registered different types leave the workflow untold, and the protocol is registered anew or handed over. Where the type a first measurement registered cannot be read — its record or its text is lost —, no exploratory release is assumed: the protocol is held as a confirmatory one until the record is back."

New paragraph, proposed (A2, A5, A6):

"**In exploration each run stands by its own text.** An exploratory protocol may change its question, method, data selection, filter, analysis or criterion between runs; a success criterion is optional, and one added or changed later judges only the runs measured under it. A change is declared as a step on the run it builds on (`[builds_on]`), with its occasion and its reason. `runlog` refuses a step whose basis is not a completed measurement of the same protocol in the area; a repeat is no basis. Before a number is released, the answering run and every basis its steps name are read back under the text each started under, and each step's declared changes equal the differences of the two texts in the registered parts, no more and no fewer. A run in that chain whose text or step cannot be read back holds the release; it is never read as a run without a step. The first measurements are told by the Git history, not by the clock or the start files: every measurement whose recorded commit has no other measurement's commit among its ancestors — on one line of history the runs at the earliest measuring commit, and one group per branch where the history diverged. A run whose commit cannot be placed is counted among them as a precaution, since nothing shows that another came before it; that makes it a possible first measurement, not a valid registration: whether the text it started under can be read back is checked on its own, and where it cannot, the release is held. Each of them stands by its own text; where they differ, no step is owed, and the difference is the analysis audit's to see. A later run measured without a step repeats the registration of one of them; a change it brings undeclared is held, and the way on is the step declared and a new run, since a run keeps the text it ran under. Once the protocol adopts a run as its result, the protocol as it stands is that run's text in what the number is about; to go on exploring after an adoption, the adoption is withdrawn with its reason, and the run and its number stay. The comparison is of the registered protocol parts only: a method changed in code alone is the analysis audit's to find (LAB-050 Analysis audit before reporting). What the task asks for stays owed in exploration — a requested comparison, the quality checks, the null condition where the instrument's validity needs it — and so do the checks the repeat cost owes."

The paragraph "A measurement that started keeps counting" (`:75`) gains two sentences that separate the order from the type; see B1.

#### LAB-004 Identifiers make the intent addressable (`:87`), A1 and A2

Now: "A fit (a model trained or adjusted in the experiment) and an apply (a model used unchanged) have a bar and register it, whatever the tier." Wrong in exploration (A2). The paragraph also never says where the reported number stands (A1); `[kept]` occurs in no rule body of the standard, only in the version line and under "Changes" (`grep -n '\[kept\]' labkit/docs/standard.md`: lines 3 and 593).

Proposed replacement: "Every kind names the number it reports in the head's `[kept]` table — `key`, the `metrics.json` key the run holds as a finite number, and `unit`. Where a fit (a model trained or adjusted in the experiment) or an apply (a model used unchanged) registers a criterion, it judges exactly the kept number and adds only its threshold and verdict. In confirmation the criterion is required, whatever the tier; in exploration it is optional. Only a protocol that registers no criterion reports the kept number without a success verdict."

The sentence before it stays: "a computation (`kind = "compute"` in the head, standard 0.22: a number that judges no prediction and so cannot pass trivially) registers nothing unless its prose names a promise id […], and owes neither tables nor a success criterion". Its clause "its question, data, exclusions and unit are its registration" is unchanged by the branch.

#### LAB-011 Required-field check (`:109`), A3

Now: "A full run (`run_kind="measurement"`) on a protocol without `frozen = true` or with an empty `preflight_audit` is refused by `runlog` before `mkdir`". Incomplete: the type is refused at the same place, at both costs.

Proposed, appended to the paragraph: "At every repeat cost a full measurement run presupposes a stated `type` and a valid `[kept]` table; the checks before the start and, at high repeat cost, before the freeze hold this."

#### LAB-015 Preflight audit before freezing (`:121`), A14

Now: "the finding names the missing information and the check that settles it, with what its value must show; the check is written and measured, and the follow-up judges its value". Incomplete: a check that asks for code the auditor was not shown in full is neither written nor measured.

Proposed, inserted after that sentence: "Where the missing information is code the auditor was not shown in full — a diff between two runs past the audit's budget, or a file as a run started from it —, the check names that evidence, nothing is built or measured, and the decision `fixed` says only that the evidence is supplied: it confirms neither the code nor the claim. The follow-up audit is shown the evidence and judges the suspicion; evidence that cannot be shown leaves the finding open."

#### LAB-017 The number of audits follows the cost tier (`:182`), A2 and A6

Now, three sentences: "**At `low`, the criterion freezes once, the instrument never.** The criterion is fixed before the number exists and does not move afterwards (a plain computation registers none — see the `[[promise]]` tables above)." and "If the criterion changes, it is a new experiment at any tier (LAB-003 No run without an intent paragraph)." and "`runlog` demands at `low` only the written criterion instead of the freeze". All three are wrong for an exploratory protocol.

Proposed: "**At `low`, a confirmatory criterion freezes once, the instrument never.** In confirmation the criterion is fixed before the number exists and does not move afterwards (a plain computation registers none — see the `[[promise]]` tables above)." and "If a confirmatory criterion changes, it is a new experiment at any tier; in exploration a criterion is added or changed as a declared step, and earlier runs keep theirs (LAB-003 No run without an intent paragraph)." and "`runlog` demands at `low` the written registration instead of the freeze — the question, the type, the kept number, and the criterion where it is owed".

#### LAB-041 Generate numbers, don't retype them (`:302`, `:304`), A1, A9, A10
